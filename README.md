# us_monitor · 美股监控工具

覆盖全部美股 + ETF，按**成交额降序**只监控前 30 名，默认用 **60 分钟 K 线**观察形态。
纯本地运行、无需 API Key、无第三方依赖（只用 Python 标准库）。

```
双击 start.bat  →  浏览器自动打开 http://127.0.0.1:8021
```

---

## 一、数据源：选了谁、为什么选、限制在哪

全部是**免费、无需注册、无需 API Key** 的公开行情接口。下面是逐个实测的结论
（测试时间 2026-09-24，测试机为中国大陆家宽）。

### 主源①：东方财富 `push2.eastmoney.com` —— 负责「谁在成交额前 30」

| 用途 | 接口 | 实测 |
|---|---|---|
| 全市场成交额榜 | `clist/get`，`fs=m:105,m:106,m:107`，`fid=f6` | 1 个请求返回 **13,832 只**（NASDAQ+NYSE+AMEX，含 ETF），0.48 秒，**服务端已按成交额排好序** |
| 60 分钟 K 线 | `push2his`，`klt=60` | 0.16～0.22 秒/只，字段含 开/收/高/低/量/**成交额/振幅** |

**为什么必须是它**：它是目前唯一一个「免费 + 免 Key + 在服务端就能按成交额排序全市场」的源。
换成任何别家（Yahoo / Nasdaq / Alpaca / Finnhub），要么没有全市场快照，要么排序参数无效，
要么必须先自备几千个代码再自己算 —— 所以榜单这一层没有替代品。

**⚠️ 最重要的限制：有 IP 级风控，且会连坐 K 线接口。**
我在探测阶段为摸清接口，在 2 分钟内打了约 26 次请求，结果**`push2` 与 `push2his` 两个域名同时开始
拒绝连接**（`RemoteDisconnected`），并且持续了 **50 分钟以上**仍未恢复（同期 `quote.eastmoney.com`
网页正常，说明是 API 级限流，不是封 IP）。

因此本工具对它的策略是：

- 榜单**硬间隔 60 秒**（`config.json → board.min_interval_sec`，不要调小）；
- K 线**5 分钟一轮**（60 分钟 K 线本来 60 分钟才出一根，没必要高频）；
- 批量取 K 线时逐个摊开（`kline.gap_ms = 150`），并发压到 3；
- 一旦被限流，自动进入 **60s → 120s → 300s → 600s → 900s** 指数退避，期间**降级而不是报错**。

按这套节奏跑，请求量约 10 次/分钟，是我探头时的 1/10 以下。

**其余限制**：非官方公开 API、无文档、无 SLA、字段随时可能变；行情延迟官方未承诺（下文详述）。

### 主源②：新浪财经 —— 负责「60 分钟 K 线」与「当前那根 bar 的实时价」

| 用途 | 实测 |
|---|---|
| 60 分钟 K 线 | 单只 **0.3～0.4 秒**，一次返回 **1023 根**（接口上限）≈ **147 个交易日** ≈ 7 个月，含成交量与**成交额** |
| 限流 | **连续 8 次调用全部成功，零风控迹象** |
| 覆盖 | 个股 + ETF 都通（AAPL / SPY / QQQ / TQQQ 实测通过） |
| 实时报价 | `hq.sinajs.cn/list=gb_aapl`，**批量 60 只/次**，盘前/盘中/盘后都有值，秒级更新 |

**为什么它是 K 线主力**：美股**盘前/休市时它返回的就是完整历史行情**（最后一根＝上一交易日收盘），
所以「没开盘也能看到 K 线与形态」这个需求天然成立；再加上它不限流、历史比东财长 7 倍。

**限制**：返回 JSONP（`var _AAPL_60_1=([...])`）需要剥壳；**时间戳是美东时间 ET**（与东财的北京时间差 12/13
小时），所以返回里带 `tz` 字段、界面按 ET 标注；只有单只接口没有批量；非公开文档。

> ⚠️ **踩坑记录（2026-10-08 实测）**：分钟 K 线接口**不返回「正在走的那根」**——盘前 07:30 ET 请求，
> 最后一根仍是上一交易日 16:00 且是收盘价；换 5 分钟周期也只到 16:00。所以「当前 60 分钟涨跌」
> **不能用 K 线数组最后一根算**，必须用 `hq.sinajs.cn` 的实时价补齐。详见 `current_bar.py`。

### 主源③：腾讯 `qt.gtimg.cn` —— 负责「现在多少钱」

| 用途 | 实测 |
|---|---|
| 实时快照（含成交额） | **批量 400 只，0.13 秒返回**；连续调用十余次**零风控**；国内直连 |

返回是 GBK 编码的 `~` 分隔字符串，字段位置是约定俗成的：`[3]现价 [4]昨收 [5]今开 [6]成交量
[30]时间 [31]涨跌额 [32]涨跌幅 [33]最高 [34]最低 [37]成交额 [44]总市值`。

**为什么需要它**：榜单 60 秒才能取一次（东财风控），但价格必须是实时的 —— 所以榜单负责
「谁在前 30」，腾讯负责「现在多少钱」，两者分工。

**限制**：**没有美股分钟级 K 线**（`mkline` / `UsKlineController` 只覆盖 A 股港股，传 `m60` 直接
`param error`）；日线虽然能取，但实测**只有首日和最新两根**，中间残缺，所以**不能拿来当 K 线备胎**，
本工具没有用它。

### 备选源

| 源 | 用途 | 实测与限制 |
|---|---|---|
| `api.nasdaq.com` | 单只实时报价 | 返回的是**真·实时价，且含盘前盘后**（实测 07:31 ET 拿到盘前 337.11）。但单只查询慢（2～3 秒）、榜单排序参数无效（传 `sortColumn` 返回顺序不变）、历史只有日线、非公开接口 |
| `quote.cnbc.com` | 批量快照（备用） | 0.7 秒可批量，含 `ExtendedMktQuote` 盘前盘后；无历史 K 线 |

### 已排除（别浪费时间）

| 源 | 排除原因 |
|---|---|
| **Yahoo Finance** | `query1/query2` 三个端点**全部 403**，国内直接不可用（`yfinance` 同理） |
| Polygon / Massive | 免费档只有 EOD，5 次/分钟；实时要 $29 起 |
| Alpha Vantage | 免费 25 次/**天**，且延迟 15 分钟 |
| Twelve Data | 免费档 800/天但**是延迟数据** |
| Finnhub | 免费档确实有实时（60 次/分钟），但**需要注册 Key** —— 想用可以，见第五节扩展 |

### 「实时」到底有多实时（如实说）

本次验证全部发生在**美股盘前**（北京时间 19:30–20:20，美东 07:30–08:20），这个时段：

- 腾讯与东财给出的都是**上一交易日收盘价**（SPY 767.81），盘前不动；
- 只有 NASDAQ 官方接口给出了盘前价（763.88）。

所以**盘中的实时性我无法在这个时段实测确认**，文档里不做承诺。可以确定的是：
需要盘前盘后数据时，走 NASDAQ 源（工具详情页已接入）。

## 三、核心功能实现

### 1. 成交额前 30 是怎么算出来的

东财一次请求 `pz=200`，它已经在服务端按成交额降序排好；前 30 展示，**整个 200 只写进
`cache/universe.json` 当候选池**。这样一旦东财被限流，可以直接用这 200 只 + 腾讯实时成交额
在本地重排，榜单照样出得来 —— 实测重建结果与东财原始榜单**完全一致**
（SPY 422亿 > QQQ 246亿 > MU 232亿 > META 231亿 > NVDA 202亿 …）。

### 2. 三层刷新节奏（这是关键）

| 层 | 内容 | 间隔 | 为什么 |
|---|---|---|---|
| 价格层 | 现价/涨跌幅/成交额/高低 | **18 秒** | 腾讯不限流，价格必须新 |
| 榜单层 | 谁在成交额前 30 | **60 秒** | 东财风控约束的硬下限 |
| K线层 | 60 分钟 K 线 + BOLL | **300 秒** | 60 分钟才出一根新 K 线，高频没意义 |

服务端对每层各带独立缓存，前端刷新再快也打不穿到上游。

### 3. 60 分钟 K 线（美股没开盘也能看）

主源**新浪财经**，一次拿到 1023 根 ≈ 147 个交易日。时间标签是**美东时间**：

```
10:30 / 11:30 / 12:30 / 13:30 / 14:30 / 15:30 / 16:00     ← 每天 7 根，最后一根是半小时
```

**盘前 / 休市时它给的就是历史行情**（最后一根＝上一交易日收盘），不用等开盘就有图可看。
界面右上角会实时判断交易时段并标注：`交易中 / 盘前 / 盘后 / 已收盘 / 休市`，
K 线面板标题旁同时显示「历史行情 · 最后 K 线 09-23 16:00（美东时间）」。

前端 Canvas 自绘：**蜡烛图 + BOLL(20,2) 上/中/下轨 + 底部成交量柱**。备源东财（时间标签为北京时间）。

**图表交互**（默认只显示最近 **21 根 ≈ 3 个交易日**）：

| 操作 | 效果 |
|---|---|
| 鼠标悬停 | 十字光标 + 该根明细（开 / 高 / 低 / 收 / 涨跌 / 振幅 / 成交量 / 成交额），涨跌以**前一根收盘**为基准 |
| 滚轮 | 缩放，**以光标位置为锚点**（光标下那根 K 线在屏幕上保持不动） |
| 按住拖动 | 平移，右拖看更早、左拖看更新 |
| 双击 | 复位回默认视图 |
| 触屏单指 / 双指 | 平移 / 缩放 |

缩放范围 **8 ～ 140 根**；一直贴着最新行情时，缩放后会**继续保持贴边**（不会一放大就脱离最新）。
默认窗口根数由 `config.json → ui.chart_bars` 控制。

### 4. 降级链（不编造数据是原则）

| 故障 | 行为 |
|---|---|
| 东财榜单不可用 | 本地候选池 × 腾讯实时成交额 → 本地重排，界面顶部标注「降级中」及原因 |
| 东财榜单与候选池都不可用 | 展示上一次成功快照，并标注快照时间 |
| 新浪 K 线不可用 | 自动改走东财 K 线（时间标签换成北京时间） |
| 两个 K 线源都不可用 | 界面如实提示「本次未取到」，缺失标的**保留上一次成功结果**，不伪造 |
| 腾讯快照不可用 | 退回东财榜单自带的价格字段 |
| 详情页实时价 | 腾讯 → NASDAQ（含盘前盘后）→ CNBC |

### 5. 进出榜流水

表格下方独立一张卡（不是塞进别的面板里）。记录谁在什么时刻进入/跌出前 30、原因和当时的数值。
榜单变动是瞬时发生的，事后翻表格根本看不出来 —— 只能靠它回查。

### 6. 监控条件（规则）

`rules.py` 内置 4 条，`config.json` 里开关：

| 规则 | 默认 | 作用 |
|---|---|---|
| `top_amount` | 开 | 成交额前 N 名入池（唯一的 filter 类规则） |
| `pct_spike` | 开 | 日内涨跌幅 ≥ 5% 打标 |
| `amount_surge` | 开 | 本根 60 分钟成交额 ≥ 前 20 根均值的 2 倍 |
| `boll_break` | 关 | 现价贴近/突破 60 分钟布林中轨 |

### 7. 自选框（60上涨 / 60下跌）

在成交额前 30 内，按**「当前 60 分钟 K 线的涨跌幅」**分流成两个自选框：

| 自选框 | 条件 |
|---|---|
| **60上涨** | 成交额前 30，且当前 60 分钟 K 线涨跌幅 **≥ +0.5%** |
| **60下跌** | 成交额前 30，且当前 60 分钟 K 线涨跌幅 **≤ −0.5%** |

**「当前 60 分钟 K 线」的准确定义**（这是这一节唯一需要看懂的地方）：

1. 60 分钟 bar 的美东时间是 `10:30 / 11:30 / 12:30 / 13:30 / 14:30 / 15:30 / 16:00`
   （时间戳 = 该根的**收盘时刻**，与新浪返回的 `d` 字段一致）；
2. **未走完也算** —— 比如 13:20 ET 时算的是 13:30 那根，收盘端用**实时价**填，
   开/高/低由「上一根收盘 + 实时价」补齐；
3. 涨跌幅的**基准 = 该根的上一根收盘**（09:30–10:30 那根的基准就是上一交易日 16:00）；
4. K 线源若还没吐出当前这根，就完全靠实时价推算（实测盘前/盘中它确实会滞后）。

界面上那根**虚线半透明蜡烛**就是它，浮层标「当前（未走完）」。

> ⭐ **全天候展示**：两个框在盘前/盘后/休市都看得见（框上有「盘前」「盘中」「盘后」「休市」角标）。
> 盘中按 60 分钟 K 线口径筛，盘前/盘后按「距昨收」口径筛 —— 两种口径的含义不同，详见第 8 节。

**加一个新框**：`config.json → watchlists` 加一行即可，`server.py` / 前端都不用改：

```json
"watchlists": {
  "up60":   { "name": "60上涨", "enabled": true, "side": "up",   "thr": 0.5 },
  "down60": { "name": "60下跌", "enabled": true, "side": "down", "thr": 0.5 },
  "up60_big": { "name": "60大涨", "enabled": true, "side": "up", "thr": 2.0 }
}
```

`side`：`up` = 涨幅 ≥ thr 入选，`down` = 跌幅 ≤ −thr 入选。

> 📌 **口径提醒**：这里的涨跌幅是**相对上一根 60 分钟 K 线收盘**的，
> 与「相对昨日收盘的日内涨跌幅」（表格里的「涨跌幅」列）**不是同一个数**，两个都给了。

### 8. 时段策略：全天候展示，口径随时段变

自选框**全天候展示**（老大 2026-10-08 定调），价格也全天候刷新。
但**涨跌幅的口径随时段不同**，靠框上的时段角标区分：

| 时段（美东） | 榜单价格 | 涨跌幅口径 | 自选框 | 详情页「当前 bar」 |
|---|---|---|---|---|
| **盘中** 09:30–16:00 工作日 | 实时价 | **当前 60 分钟 K 线**（未走完按实时价），基准 = 上一根 60 分钟收盘 | 正常筛选 + 展示，角标「盘中」 | 有（虚线幽灵 bar） |
| 盘前 04:00–09:30 | 实时价 | **距昨收**（实时价 vs 上一交易日收盘） | 正常筛选 + 展示，角标「盘前」 | 有（t=null，非 K 线口径） |
| 盘后 16:00–20:00 | 实时价 | 距昨收 | 正常筛选 + 展示，角标「盘后」 | 同上 |
| 休市（周末/节假日） | 上一收盘 | 0.00%（无实时价） | 空框 + 角标「休市」 | 无实时价 |

> 📌 **两种涨跌幅的含义不同，别混**：
> * 盘中 `+0.6%` = 这一小时比上一小时涨了 0.6%（60 分钟 K 线口径）；
> * 盘前 `+0.6%` = 现在比昨天收盘涨了 0.6%（距昨收口径）。
> 盘前这个数在开盘瞬间会「归零重算」，因为那时基准换成 09:30 那根 60 分钟 K 线了。

**⚠️ 必须躲的基准陷阱**（2026-10-08 实测）：
盘前/盘后报价源自带的「昨收」是**错的** —— 新浪 `p[26]` 与腾讯 `p[4]` 在盘前给的
都是**前前一日**收盘。MU 报 `prev_close=1045.56 / +4.06%`，而 10-07 真实收盘是
`1087.835`，实际只 `+0.015%`（差 4 个点）。
⇒ **昨收一律以 60 分钟 K 线尾部的收盘价为准**（`datasource._last_closes` 批量取、
`server._fix_rt_baseline` 兜底、`current_bar.resolve_current_bar` 用它当分母）。
报价源自带的 `prev_close/pct/chg` 已改名 `raw_*`，标明不可直接用。

## 四、运行方式

### 双击启动（推荐）

桌面上已放好入口：**`美股监控.bat`** —— 双击即可，会自动检测服务是否在跑、起服务、并打开浏览器。

项目内另有一份等价的 `us_monitor\start.bat`。

> 两个 bat 都是 **GBK 编码**写入的（本机 cmd 按 GBK 解析 bat），所以里面带中文提示和中文路径都不会乱码。
> 如果你要改这两个文件，**别用会输出 UTF-8 的编辑器保存**，否则中文会变成乱码导致路径失效。

### 命令行

```bash
python app.py                  # 用 config.json 的端口（8021）
python app.py --port 8099      # 换端口
python app.py --no-browser     # 不开浏览器（后台跑）
```

### API（想自己接一手）

| 端点 | 说明 |
|---|---|
| `GET /api/board` | 成交额前 30 + 进出榜流水 + 数据源与降级状态 |
| `GET /api/klines` | 批量 60 分钟 K 线摘要（BOLL 中轨/位置/量能倍数/标签） |
| `GET /api/watchlist` | 自选框：60上涨 / 60下跌（含每只的当前 bar 开高低收/基准/涨跌幅/是否走完） |
| `GET /api/detail?symbol=AAPL` | 单只：K 线全文 + 实时报价 + 当前未走完的 bar |
| `GET /api/health` | 各源健康状态，含东财风控冷却倒计时 |

## 五、扩展空间

### 加数据源

`datasource.py` 里每个源都是一个类，只要实现 `health()`，然后在 `MarketData` 里挂一行即可。
想接 **Finnhub / Alpaca**（都有免费实时，但需要注册 Key）：

```python
# datasource.py
class FinnhubSource:
    NAME = "Finnhub"
    def __init__(self, token): self.token = token
    def quote(self, symbol):
        return json.loads(http_get(f"https://finnhub.io/api/v1/quote?symbol={symbol}&token={self.token}"))
```

在 `config.json` 加 `"finnhub": {"token": "..."}`，然后在 `MarketData.realtime` 的降级链最前面插进去。

### 加监控条件

在 `rules.py` 抄一个类，然后在 `_CLASSES` / `_META` 各登记一行，`config.json` 里加开关 —— 
前端和 server 都不用改。文件里已经留了三个注释掉的样板（均线金叉、跳空、排名跃升）。

### 加周期

`config.json → kline.period` 改成 `15 / 30 / 60 / 101(日)` 即可（东财 `klt` 支持这些值），
前端 `ui.periods` 同步改一下就能出切换按钮。

### 加指标

`indicators.py` 是纯函数集合，加一个 `macd(bars)` 后在 `summarize()` 里带出去，前端 KV 面板加一格。

- 颜色按 A 股习惯：**红涨绿跌**（与美股相反）。
